# Implementation Plan: Issues #07 + #08
# Role/Permission Schema & Permission Middleware

---

## Ticket #07 — Role & Permission Schema

Status: ready-for-agent

### What to build

Create the database schema for Roles and permissions per ADR-0007. A Role is a named, reusable bundle of permissions defined by a Tenant Admin. Users inherit their Role's permissions, with individual per-user overrides possible. Permissions are tenant-wide — never scoped to specific Locations.

### Acceptance criteria

- [ ] `roles` table exists with id, tenant_id, name, and a permissions payload (e.g. JSONB or a normalized permissions table)
- [ ] `user_role_assignments` table links users to Roles
- [ ] `user_permission_overrides` table stores per-user permission additions/revocations
- [ ] RLS policies applied — roles and overrides are tenant-scoped
- [ ] A query helper in `packages/db` resolves the effective permission set for a given user (role permissions merged with overrides)
- [ ] Migration runs cleanly

### Blocked by

- #05 Tenant & User schema + RLS bootstrap ✅

## Ticket #08 — Permission Middleware

Status: ready-for-agent

### What to build

Add API middleware that resolves and enforces permissions on every protected route. The middleware reads the authenticated user's Role and per-user overrides, computes the effective permission set, and attaches it to the request context. Routes declare the permission they require; the middleware rejects requests that don't satisfy it.

### Acceptance criteria

- [ ] Middleware resolves effective permissions for the authenticated user on each request
- [ ] A helper (e.g. `requirePermission('manage:locations')`) can be composed onto any API route
- [ ] Requests lacking the required permission receive a `403` response
- [ ] Unauthenticated requests are rejected before permission resolution
- [ ] At least one protected route uses the middleware in a test that verifies allowed and denied cases

### Blocked by

- #07 Role & permission schema (implemented in this session)

## Spec: Role & Permission Schema

### Permission vocabulary

Permissions are strings in the form `action:resource`. The full set is already defined in `packages/shared/src/permissions.ts`:

```typescript
export const PERMISSIONS = [
  'manage:users',         // invite users, change roles, set overrides
  'manage:locations',     // create, edit, delete Locations
  'manage:surveys',       // create, edit Survey builder
  'manage:inspections',   // schedule Inspections, assign Inspectors
  'finalize:inspections', // run the Finalization flow
  'manage:incidents',     // close Incidents
  'conduct:walkthroughs', // Field App: complete Walkthroughs
] as const

export type Permission = (typeof PERMISSIONS)[number]
```

### Database schema

```typescript
// packages/db/src/schema/roles.ts
export const roles = pgTable('roles', {
  id:        uuid('id').primaryKey().defaultRandom(),
  tenantId:  uuid('tenant_id').notNull().references(() => tenants.id, { onDelete: 'cascade' }),
  name:      text('name').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
})
```

```typescript
// packages/db/src/schema/role-permissions.ts
export const rolePermissions = pgTable('role_permissions', {
  roleId:     uuid('role_id').notNull().references(() => roles.id, { onDelete: 'cascade' }),
  permission: text('permission').notNull(),
}, (t) => ({
  pk: primaryKey({ columns: [t.roleId, t.permission] }),
}))
```

```typescript
// packages/db/src/schema/user-role-assignments.ts
export const userRoleAssignments = pgTable('user_role_assignments', {
  userId:     uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  roleId:     uuid('role_id').notNull().references(() => roles.id, { onDelete: 'cascade' }),
  assignedAt: timestamp('assigned_at', { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  pk: primaryKey({ columns: [t.userId, t.roleId] }),
}))
```

```typescript
// packages/db/src/schema/user-permission-overrides.ts
export const userPermissionOverrides = pgTable('user_permission_overrides', {
  userId:     uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  permission: text('permission').notNull(),
  granted:    boolean('granted').notNull(), // true = grant override, false = revoke override
  updatedAt:  timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  pk: primaryKey({ columns: [t.userId, t.permission] }),
}))
```

### RLS

All four tables are tenant-scoped. `role_permissions` and `user_role_assignments` join to their parent table for the tenant filter — they have no direct `tenant_id` column.

### Context

Issue #08 (permission middleware) is blocked by #07 (role & permission schema). Neither is implemented yet — the DB currently has only `tenants`, `users`, and `sessions`. Both are implemented together.

The permission model follows ADR-0007: roles-with-overrides. Users inherit permissions from assigned Roles; per-user overrides can add or revoke individual permissions. The middleware resolves this effective set on every protected request.

**Step 3 — Create `packages/db/src/permissions.ts`**

```typescript
export async function resolvePermissions(userId: string): Promise<Set<Permission>>
```

Uses the superuser `db` client (bypasses RLS — consistent with `getAuthContext`). Algorithm:
1. SELECT roleIds from `userRoleAssignments` WHERE userId = $1
2. If any, SELECT permissions from `rolePermissions` WHERE roleId IN (...)
3. SELECT overrides from `userPermissionOverrides` WHERE userId = $1
4. Build Set from role perms; apply overrides (`granted:true` adds, `granted:false` deletes)

Export from `packages/db/src/index.ts`.

**Step 4 — Generate migration**

Run `pnpm db:generate` (drizzle-kit) to produce the next numbered `.sql` file in `packages/db/src/migrations/`.

**Step 5 — Edit generated migration to add RLS**

Append to the generated SQL:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE
  ON roles, role_permissions, user_role_assignments, user_permission_overrides
  TO compliance_app;

ALTER TABLE roles ENABLE ROW LEVEL SECURITY;
ALTER TABLE role_permissions ENABLE ROW LEVEL SECURITY;
ALTER TABLE user_role_assignments ENABLE ROW LEVEL SECURITY;
ALTER TABLE user_permission_overrides ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON roles
  USING (tenant_id = current_setting('app.current_tenant_id')::uuid);

CREATE POLICY tenant_isolation ON role_permissions
  USING (role_id IN (
    SELECT id FROM roles
    WHERE tenant_id = current_setting('app.current_tenant_id')::uuid
  ));

CREATE POLICY tenant_isolation ON user_role_assignments
  USING (role_id IN (
    SELECT id FROM roles
    WHERE tenant_id = current_setting('app.current_tenant_id')::uuid
  ));

CREATE POLICY tenant_isolation ON user_permission_overrides
  USING (user_id IN (
    SELECT id FROM users
    WHERE tenant_id = current_setting('app.current_tenant_id')::uuid
  ));
```

**Step 6 — Apply migration**

Run `pnpm db:migrate`.

**Step 7 — Tests for #07**

File: `packages/db/src/__tests__/permissions.integration.test.ts`

Seven `resolvePermissions` cases:
- No roles, no overrides → empty set
- One role with two permissions → those two
- Two roles → union (no duplicates)
- Role grants `manage:users`; override revokes it → empty set

### Phase 2 — Issue #08: Permission Middleware

**Step 8 — Create `apps/admin/src/lib/permissions.ts`**

```typescript
import { NextResponse } from 'next/server'
import { getAuthContext, type AuthContext } from './auth'
import { resolvePermissions } from '@compliance/db'
import type { Permission } from '@compliance/shared'

type Handler = (req: Request, ctx: AuthContext) => Promise<Response>

export function requirePermission(permission: Permission) {
  return (handler: Handler) =>
    async (req: Request): Promise<Response> => {
      const ctx = await getAuthContext(req)
      if (!ctx) return NextResponse.json({ error: 'unauthenticated' }, { status: 401 })
      const perms = await resolvePermissions(ctx.userId)
      if (!perms.has(permission)) {
        return NextResponse.json({ error: 'forbidden' }, { status: 403 })
      }
      return handler(req, ctx)
    }
}
```

**Step 9 — Add protected stub route `apps/admin/src/app/api/locations/route.ts`**

```typescript
import { NextResponse } from 'next/server'
import { requirePermission } from '@/lib/permissions'
import type { AuthContext } from '@/lib/auth'

export const GET = requirePermission('manage:locations')(
  async (_req: Request, _ctx: AuthContext) => NextResponse.json({ locations: [] })
)
```

**Step 10 — Tests for #08**

File: `apps/admin/src/__tests__/permissions.integration.test.ts`

Five cases against `GET /api/locations`:
- Unauthenticated request → 401
- Authenticated, no roles/overrides → 403
- Authenticated, role has `manage:locations` → 200
- Authenticated, direct override `manage:locations` (`granted: true`) → 200
- Authenticated, different permission only (e.g. `manage:users`) → 403
